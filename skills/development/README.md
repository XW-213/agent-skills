# development — 后端开发线

工程方向的技能：从需求到可运行的服务，以及把别人的项目读懂。

Engineering skills: from requirement to running service, and reading someone else's codebase.

## 状态

规划中。这个分支目前只有结构，还没有可用的技能。

## 已确定的选题方向

| 方向 | 大致内容 | 备注 |
|---|---|---|
| 项目脚手架 | 按技术栈生成可直接运行的最小工程，含配置与目录约定 | Java / Spring Boot 优先 |
| 代码阅读 | 给定陌生仓库，产出模块地图、调用链、入口清单 | 输出给"接手项目"的人看 |
| 调试排障 | 从报错到根因的定位流程，不猜、逐层缩小 | 强调复现步骤与验证方法 |
| 接口设计 | 资源建模、状态码、错误结构、幂等性检查 | 附反例，说明为什么这样不行 |
| 数据库设计 | 表结构、索引、约束、迁移脚本 | 与安全线的注入问题联动 |

## 这一线的偏好

- **能跑优先。** 示例代码必须真的能运行，不能是"示意性伪代码"。
- **说清代价。** 每个方案都要写它牺牲了什么；只讲优点的设计方案没法用来做决策。
- **不隐藏版本。** 依赖版本、JDK 版本、操作系统差异都写出来，避免"我这里能跑"。

## 交叉点

和安全线共享 Java 生态（反序列化、依赖漏洞、鉴权框架）；和教育线共享文档能力（技术方案、README、故障复盘的写法都讲究结论先行）。
